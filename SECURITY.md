# Security policy

Do not post credentials, raw task evidence, private chat transcripts, session IDs, or local database files in public issues or pull requests. If the eventual GitHub repository enables private vulnerability reporting, use that channel; otherwise ask the maintainer for a private contact channel without including exploit details or secrets in the public request.

Supported scope for the public beta will be the tagged release only. Live Feishu/CLI deployments must supply their own identities and credentials and remain loopback/private-network bound unless independently security-reviewed. See [release hygiene](docs/security.md).
